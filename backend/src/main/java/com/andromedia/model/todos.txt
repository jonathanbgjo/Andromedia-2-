--- Security / scaling backlog (from code review) ---
[ ] Login brute-force protection: rate limiting / temporary lockout on
    /auth/login (e.g. bucket4j, or a gateway/WAF rule). Needs an infra decision
    (in-memory won't hold across instances).
[ ] Registration email enumeration: /auth/register reveals whether an email
    exists. Fully fixing this needs an email-verification flow (confirm before
    activating) rather than an immediate "already registered" response.
[ ] Auth storage: move the JWT from localStorage (XSS-exfiltratable) to an
    httpOnly, SameSite cookie set by the backend, and drop the bearer header +
    credentials:"include" mix. Frontend + backend coordinated change.
[ ] Pagination: /api/videos, /api/videos/search, comments, and history return
    unbounded lists. Add Pageable/Page<> — coordinated change with the frontend
    consumers (changes response shape).
[ ] Feed like-counts: current per-video COUNT query is O(n) queries on the feed.
    A single GROUP BY projection (id,…,COUNT(likes)) would make it one query.
